## What STEVE does (facts, 2026-11-04; the docs win if they differ, report it)
- Declare in the catalog, on the action: "x-steve": {"toolpath": {"title": <=80 chars, "description": <=1000 chars, "cutters": ["flat"]}}. It is the ONLY action-level x-steve key. Inputs are VALUES ONLY (no x-steve inputs), may not be named part, setup, tool, stock, request, or start with steve_. Changing a toolpath action's inputs or cutters takes its permission away until the person allows it again.
- Such an action is never run on its own (STEVE refuses other runs with 409 toolpath_generate_only). A person or agent presses "Generate toolpath" on the operation.
- Run inputs: part (STEP of the part at the linked revision, one-time download, check sha256), request (ToolpathRequest JSON; lengths mm, positions in the SETUP'S WORK FRAME), steve_request_sha256 (the answer must repeat it), stock (GLB, only for an operation after another one; metres, Z up, work frame, staircase of cell_mm cells, up to 1,000,000 faces; snapshot_sha256 equals request.predecessor_stock_sha256), plus our own settings (also inside request.settings). First operation in a setup: predecessor_stock_sha256 is null and the blank is request.setup.stock_mm.
- Answer: upload ONE file toolpath.json with PUT /connect/v1/runs/{id}/files/toolpath.json, then report succeeded. Format: {"format":"steve_connector_toolpath","version":1,"units":"mm","coordinate_space":"work","request_sha256":<steve_request_sha256>,"moves":[...]}. Moves: {"kind":"rapid","end_mm":[x,y,z]}, {"kind":"feed","end_mm":[x,y,z],"feed_mm_min":F}, {"kind":"arc","end_mm","center_mm","direction":"cw|ccw","turns","feed_mm_min"} (arcs ONLY if request.posts_arcs is true; otherwise line segments). end_mm is the tool TIP in the work frame.
- Validation (STEVE refuses with toolpath_refused naming field/move/limit; nothing is stored): first move starts from start_tip_mm; every move inside tip_envelope and margin_box (plan one output step INSIDE each limit, posted coordinates are rounded); feeds <= the operation's feed and the machine's fastest feed; a straight plunge <= the plunge feed; last move ends at or above retract_z_mm; file <= 50 MB and 200,000 moves, strict UTF-8 JSON, no extra fields. Rapids before the first cut may leave margin_box once posted (machine home), the file still must not.
- Afterwards STEVE re-checks, converts, simulates and checks the posted program against its own stock and decides verified/checked. Our zmap remains our independent second opinion.

## Item 1: the action and its settings (James: agents and humans must be able to set them)
Name `adaptive_rough_toolpath`, cutters ["flat"] only. Inputs (all optional, values only, mm; STEVE always works in mm so NEVER apply the inch conversion the other actions use):
- stepdown_mm: default 1.0 x tool diameter, never above the flute length (James's rule: 1xD layers). min 0.05.
- optimal_load_mm: radial engagement ("ideal load", the stepover of an adaptive path). default 0.16 x tool diameter (= his 2.032 mm for the 12.7 mm tool). Range 0.02 x D .. 0.5 x D. Title it so a human reads it as stepover/load.
- stock_to_leave_mm: default 0.381 (his floor/wall leave). min 0.
- load_limit: boolean, default true (the FL-LOAD limiter that only slows feed in over-load windows).
Tool geometry (diameter, flute length, corner radius, holder) comes from request.tool, never from our own tool library; fail the run with a plain error if request.tool is not a flat end mill or lacks a field we need. Spindle rpm and feed come from the operation (the engine must not exceed them: use min(operation feed, engine feed); FL-LOAD only slows). The work frame is the setup's frame: do NOT apply our origin logic (stock_bottom_centre etc.); the part STEP and every output coordinate are in the request's work frame. Stock is request.setup.stock_mm (box). Floor/top come from the part and the request's limits; use top = stock top.
